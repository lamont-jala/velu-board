Phase 0 — what the foundation ships

Seams and scaffolding only; zero screen conversions. Tick a deliverable when it merges to main.

  1. Router facade — per-cluster protocols (SocialRouting, CommerceRouting, …) over RootVC.shared, the 414-reference god-router. View models inject the protocol; RootVC.swift is never edited by feature streams. New files only, in Classes/Navigation/.
  2. Migration kit — the blessed template: @MainActor @Observable view model, nested LoadState (loading / loaded / failed), injected protocol dependencies with production defaults, AccountManagerProtocol, hosting helpers.
  3. Social seams — comments, the report flow, and clip options/share become reachable only via router methods, so social features stop instantiating each other's view controllers.
  4. VeluTests verified — the existing Swift Testing target (already wired into every scheme) is where each converted screen's view-model tests land, starting day one.
  5. Buildable folders — synchronized folders end per-file pbxproj registration. Heads-up: the first conversion bumps the project format (60 → 77) for everyone; Xcode 16+ required, one-way.

    Every screen, one pipeline

    The unit of work is a single screen ≈ a single PR. Avengers, assemble — in this order, every time.

    thorCommitConventional Commits, staged by explicit path.

    What keeps merges clean

    Exclusive directory ownershipYou edit your stream's directories and nothing else. Cross-boundary needs go through the router facade or the owning stream.
    Shared code is frozen after Phase 0One carve-out: extracted components land as new files in Shared/Components/, coordinated with the foundation owner.
    Nobody's PR touches the project fileA developer synchronizes each stream's folder in Xcode at kickoff; after that, adds and deletes are pbxproj-free.
    Small PRs, merged continuouslyOne screen per PR, daily rebase, no month-long mega-branches. Giant social VCs split in two: view model first, view second.

    Risks we're carrying

    No CI. Nothing catches a broken build before merge. Optional Phase 0 add-on: a minimal build-check workflow; weekly all-scheme build until then.
    The format bump is one-way. Buildable folders upgrade the whole project format on first use. Everyone on Xcode 16+ before it happens.
    Giant social VCs hide untested behavior. 2–3K-line controllers get a black-widow map before conversion and a manual DEV pass after.
    CoreData stays messy for now. View models depend on repository protocols, not CoreData. Consolidation is Phase 2, deliberately.
    Progress on this page is the canonical migration status — counts and checkmarks are live, shared, and updated by the team as PRs merge. Design truth stays in the spec.
